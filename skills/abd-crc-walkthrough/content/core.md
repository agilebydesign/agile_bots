# Core Definitions

## Behavior

**walkthrough** — Walk through the CRC model by tracing object flows and responsibilities to validate the model supports key scenarios

## Goal

Create CRC realization scenarios that trace object responsibilities and collaborations through the model, validating it can fulfill story requirements, discovering and adding missing responsibilities/collaborators/concepts to story-graph.json, and identifying improvements

## Inputs

story-graph.json with CRC model and stories, crc-model diagrams, story scenarios/acceptance criteria

## Outputs

walkthrough-realizations.md documenting traces and model updates

## Key Questions

- What is the primary purpose of these walkthroughs?
- Which epics, sub-epics, or stories should be walked through?
- What areas have architectural uncertainty or risk?
- What areas have poor understanding of object interactions?
- Are there specific acceptance criteria or scenarios that need tracing?
- What depth of walkthrough is needed?
